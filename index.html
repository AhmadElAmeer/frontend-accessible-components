Accessible components

Tabs, a modal dialog and a combobox that work with a keyboard and a screen reader, following the WAI-ARIA Authoring Practices. No dependencies and no build step: about 620 lines of JavaScript, not counting comments. Try them without a mouse.

Tabs

Arrow keys move between tabs, Home and End jump to the ends. The Tab key leaves the tab list and goes to the panel.

Automatic activation (selection follows focus)

Overview

Each component starts from plain HTML that makes sense without JavaScript: these panels are ordinary sections with headings. The script turns the headings into tabs and adds the roles, states and keyboard handling.

Manual activation, vertical

Account

With manual activation the arrow keys only move focus. Press Enter or Space to show a panel. Use this when showing a panel is slow, for example when it loads data.

Notifications

Vertical tab lists use the Up and Down arrows.

Privacy

Only the selected tab is in the Tab order, so a tab list is a single stop however many tabs it has.

Modal dialog

Focus moves into the dialog and can't leave it with Tab. Escape closes it, and focus returns to the button that opened it. The rest of the page becomes inert.

Combobox

Type to filter. Matching ignores accents and case: cote finds Côte d’Ivoire. Down opens the list, Enter picks, Escape closes the list and then clears the box.

Server search

The same list behind a simulated server that answers in 100–900 ms. Responses can arrive out of order; only the newest one is shown.
